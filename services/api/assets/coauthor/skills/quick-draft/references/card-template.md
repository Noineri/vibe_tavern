# Card Template — Quick Draft

The structural skeleton Quick Draft fills. Every field below should end up
populated in a complete draft; fields the brief doesn't cover are inferred
coherently rather than left empty. This is a *shape*, not literal frontmatter
syntax — map it onto the card's real frontmatter + section structure when you
call `write_profile` / `edit_*`.

## Frontmatter

- **name** — the character's name (or title if name is deliberately unknown).
- **tags** — 3–6 genre/content tags that help discovery; concrete, not generic ("slow-burn rivals", "comfort / angst", not just "romance").
- **creator_notes** — one or two lines for the author: the intended tone, the user's assumed role, and any content note. Optional but useful.

## `# PERSONALITY` — who they are, as behavior

- **Core fantasy in one line.** The experience this character delivers, stated as a behavior or dynamic, not an adjective.
- **Behavioral traits (3–6).** Each trait as a *mechanism*: what they do that reveals it, the trigger that surfaces it, and the cost when it misfires. Replace any adjective with the behavior that proves it.
- **One contradiction.** A condition under which they act against their own type — the thing that makes them less predictable and more memorable.
- **Voice signature.** Vocabulary, rhythm, register — the speech pattern that makes their lines recognizable. One concrete example.

## `# SCENARIO` — why the user is here, now

- **The scene premise.** Where and when the user meets this character — specific enough to act in.
- **The user's role and leverage.** Who the user is to the character and what they can affect.
- **The stakes / tension.** What's at risk in this scene, or what unresolved pressure the character is under. A scenario with no pressure is a backdrop, not a scene.

## `# EXAMPLES` — voice in motion

- **1–3 example exchanges** (character dialogue/action + an implied user turn) that demonstrate the voice signature and a representative dynamic. Script only the character; never dictate the user's thoughts or actions. Ground each in immediate sensory detail.

## Primary greeting (`firstMessage`, index 0)

- Opens **mid-action**, not with a self-introduction or static description.
- Grounded in the immediate sensory setting.
- Ends on a **hook** the user must respond to — a question, a demand, a revealed secret, a threat.

## Optional: alternate greetings (index 1+)

- One or more alternate openers that shift the starting mood, location, or premise — each a different doorway into the same character.
